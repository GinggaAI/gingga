# Brand Questionnaire - My Brand Page Fields

This document lists all fields collected on the "my-brand" page for brand profile setup.

## Overview
The my-brand page is accessible at: `/:brand_slug/:locale/my-brand`
Controller: `BrandsController#edit`
View: `app/views/brands/edit.html.haml`

---

## Field Categories and Details

### 1. Brand Identity Section
Fields that define the core brand identity:

- **Brand Name** (required)
  - Field: `brand[name]`
  - Type: Text field
  - Placeholder: Brand name

- **Brand Handle (Slug)** (required)
  - Field: `brand[slug]`
  - Type: Text field
  - Placeholder: Brand handle for URL

- **Industry**
  - Field: `brand[industry]`
  - Type: Dropdown select
  - Options:
    * Technology
    * Fashion & Beauty
    * Food & Beverage
    * Health & Fitness
    * Education
    * Entertainment
    * Business & Finance
    * Travel & Lifestyle
    * Other

- **Brand Voice**
  - Field: `brand[voice]`
  - Type: Dropdown select
  - Options:
    * Professional
    * Friendly
    * Authoritative
    * Casual
    * Inspirational
    * Humorous
    * Educational

### 2. Audience & Offer Section
Fields describing what the brand offers and why:

- **Value Proposition**

- **Mission/Purpose**
  - Field: `brand[mission]`

### 4. Target Audiences Section
Repeatable nested fields for defining target audience segments.
Field: `brand[audiences_attributes][]`

For each audience entry:

- **Audience Name**
  - Field: `audiences_attributes[n][name]`
  - Type: Text field
  - Example: "Young Professionals", "Tech Enthusiasts"

- **Demographics** (stored as JSON in `demographic_profile`)
  - Field: `audiences_attributes[n][demographic_profile]`
  - Type: Hidden field containing JSON with these sub-fields:

  - **Age Range**
    - Options: 13-17, 18-24, 25-34, 35-44, 45-54, 55-64, 65+

  - **Gender**
    - Options: All genders, Male, Female, Non-binary, Other

  - **Location Type**
    - Options: Global, Urban areas, Suburban areas, Rural areas, Metropolitan areas

  - **Specific Location**
    - Type: Text field
    - Example: "United States, Europe, Latin America"

  - **Income Level**
    - Options: Low income, Lower middle class, Middle class, Upper middle class, High income

- **Interests**
  - Field: `audiences_attributes[n][interests]`
  - Type: Text field
  - Format: Comma-separated values
  - Example: "technology, fitness, travel, food"

- **Digital Behavior**
  - Field: `audiences_attributes[n][digital_behavior]`
  - Type: Text field
  - Format: Comma-separated values
  - Example: "social_media_active, online_shopper"

## Field Summary

### Total Field Count
- **28 distinct field types**
- **Nested repeatable sections:**
  - Audiences: 6 sub-fields per entry (1 name + 5 demographic fields + 2 behavior fields)
  - Products: 4 sub-fields per entry
  - Social Channels: 3 sub-fields per entry

### Required vs Optional
Based on controller strong parameters and validation:
- **Required fields** (must be filled for "strategy ready" status):
  - Brand Name
  - Brand Handle (Slug)
  - Industry
  - Voice
  - Value Proposition
  - Mission

- **Optional fields**: All other fields are optional but recommended for better content generation

### Data Storage
- **Simple fields**: Stored directly in `brands` table
- **Virtual attributes** (handled via accessors):
  - `tone_no_go_list` → stored in `guardrails` JSON
  - `banned_words_list` → stored in `guardrails` JSON
  - `claims_rules_text` → stored in `guardrails` JSON
- **Nested associations**:
  - `audiences_attributes` → `audiences` table (has_many relationship)
  - `products_attributes` → `products` table (has_many relationship)
  - `brand_channels_attributes` → `brand_channels` table (has_many relationship)

## Technical Implementation Notes

### Controller
- Location: `app/controllers/brands_controller.rb`
- Action: `edit` (GET), `update` (PATCH)
- Service: `Brands::RetrievalService` for loading brand data
- Presenter: `BrandPresenter` for view logic

### Form Handling
- Uses Rails `form_with` helper
- Implements POST-REDIRECT-GET pattern
- Nested forms use `accepts_nested_attributes_for`
- JavaScript handlers for dynamic add/remove of nested items

### Validation
- Strategy readiness check requires minimum fields filled
- Error display at top of form
- Individual field validation on model level

### Routes
- Primary route: `/:brand_slug/:locale/my-brand`
- Also accessible via: `/:brand_slug/:locale/brand/edit`
- Both routes point to `brands#edit`
