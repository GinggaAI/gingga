**Created:** 2025-01-09
**Priority:** HIGH (Steps 1-4), MEDIUM (Steps 5-6), LOW (Steps 7-9)

## Executive Summary

The `content_structure` field is being generated by Voxa but **is not being saved** to the database, causing the 15 narrative structures system to fail silently. This document outlines the immediate fixes required and long-term refactoring recommendations.

---

## 🔴 Critical Problem Identified

### Issue: Content Structures Not Being Applied

**Root Cause Analysis:**

1. ✅ **Voxa prompt generates** `content_structure` field (confirmed in `app/services/creas/prompts.rb:242`)
2. ✅ **Validation requires** `content_structure` field (confirmed in `app/services/creas/prompts.rb:325-326`)
3. ❌ **Database table DOES NOT have** `content_structure` column
4. ❌ **Job does NOT map** the field in `map_voxa_item_to_attrs` method
5. 💥 **Result:** Field is generated by OpenAI but immediately lost

**Evidence:**

```bash
# Current columns in creas_content_items table:
$ rails runner "puts CreasContentItem.column_names.sort"
accessibility, aspect_ratio, assets, batch_number, batch_total, brand_id,
content_id, content_name, content_type, [...], template, text_base, timezone

# Missing: content_structure ❌
```

**Impact:**
- Users cannot see which narrative structure is being used
- Cannot query content by structure
- Cannot validate structure usage
- The entire Content Structures system is non-functional in production

#### Step 7: Refactor Job into Service Objects

**Problem:**
- Current file: 751 lines, 27 methods
- Violates Single Responsibility Principle
- Violates Rails Doctrine (Fat Models/Thin Controllers/Thin Jobs)
- Hard to test in isolation
- Hard to maintain

**Recommended Structure:**

```
app/services/creas/voxa_batch/
├── orchestrator_service.rb           # Main coordinator (replaces most of job logic)
├── prompt_builder_service.rb         # build_batch_system_prompt, build_batch_user_prompt, build_existing_content_context
├── content_mapper_service.rb         # map_voxa_item_to_attrs, normalize_platform, normalize_template, extract_day_of_week
├── shotplan_generator_service.rb     # ensure_shot_plan, generate_default_shotplan
├── batch_processor_service.rb        # process_voxa_batch_items, upsert_voxa_batch_item, find_existing_content_item_in_batch
├── item_persister_service.rb         # update_existing_batch_item, create_new_batch_item, generate_unique_content_name
├── error_handler_service.rb          # handle_batch_error
└── batch_finalizer_service.rb        # mark_batch_completed, finalize_voxa_processing
```

**New Job (simplified):**

```ruby
class GenerateVoxaContentBatchJob < ApplicationJob
  queue_as :default
  retry_on StandardError, wait: :exponentially_longer, attempts: 3

  def perform(strategy_plan_id, batch_number, total_batches, batch_id)
    strategy_plan = CreasStrategyPlan.find(strategy_plan_id)

    result = Creas::VoxaBatch::OrchestratorService.new(
      strategy_plan: strategy_plan,
      batch_number: batch_number,
      total_batches: total_batches,
      batch_id: batch_id
    ).call

    if result.success?
      Rails.logger.info "Voxa batch #{batch_number} completed successfully"
    else
      Rails.logger.error "Voxa batch #{batch_number} failed: #{result.error}"
      raise StandardError, result.error
    end
  rescue ActiveRecord::RecordNotFound => e
    Rails.logger.error "Strategy plan not found: #{strategy_plan_id}"
    raise
  end
end
```

**Benefits:**
- Job reduced from 751 lines to ~25 lines
- Each service has single responsibility
- Easier to test in isolation
- Reusable services across different jobs
- Follows Rails Doctrine
